## Situation

In our case, we are using `stdnum` to validate Thai national ID numbers. But until we deployed, we just realized that, a lot of our users had IDs with prefix `0x`, which [is being treated as invalid](https://github.com/koblas/stdnum-js/blob/main/src/th/idnr.ts#L55) by the library.

## What is `patch-package`?

`patch-package` is a tool that allows you to make and keep changes to your project's dependencies. Normally, you cannot directly modify the code inside `node_modules` because it will be overwritten whenever you reinstall your dependencies. `patch-package` solves this problem by creating patch files that are applied after every install.

Here's a basic usage:

1. Install `patch-package`:
```bash
npm install patch-package --save-dev
```

2. Make changes to a file inside `node_modules`. In this case, I modified the `stdnum` library to handle Thai national ID numbers with the prefix `0x`:

<PhotoView src={images[1]}><img src={images[1]} alt="patch-package saves our life" /></PhotoView>

3. Run `patch-package` to create a patch file:
```bash
npx patch-package stdnum
```

After run, a patch file will be created inside the `patches` directory in your project.

<PhotoView src={images[2]}><img src={images[2]} alt="patch-package saves our life" /></PhotoView>

4. Add a `postinstall` script in your `package.json` to apply patches automatically after every install:
```json
"scripts": {
  "postinstall": "patch-package"
}
```

Test the result again, it's working perfectly.

<PhotoView src={images[3]}><img src={images[3]} alt="patch-package saves our life" /></PhotoView>

Easy, right? Just a few steps and you can both use your dependencies and add your own fixes.

## Notes

Just one small thing I'd recommend: it's better to lock the versions of your dependencies in `package.json` so that your patches remain compatible with the installed versions.
